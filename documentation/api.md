# API reference

Base: `/api/v1`. JSON responses use `{ "success": true, "message": "Request successful", "data": ... }`; errors use `success: false`, an appropriate HTTP status, and `data: null`. Validation messages may be arrays.

Protected endpoints use `Authorization: Bearer <accessToken>`. The web proxy stores that token as an HttpOnly cookie.

| Method / route | Access | Purpose |
|---|---|---|
| POST /auth/register | Public, 5/minute | name, phone, email, password; creates PATIENT |
| POST /auth/login | Public, 10/minute | email, password; 900-second access token |
| GET /users/me | Signed in | Current safe user profile |
| PATCH /users/:id/role | ADMIN | Assign role; cannot change own role |
| GET /health | Public | Database readiness |
| GET /departments | Public | Departments and doctor counts |
| POST /departments | ADMIN | name, description, location |
| GET /doctors | Public | Optional search and departmentId query |
| GET /doctors/:id | Public | Doctor with schedules and department |
| POST /doctors | ADMIN | Create profile for a DOCTOR account |
| GET /doctors/:id/availability?date=YYYY-MM-DD | Public | Session and remaining capacity |
| PUT /doctors/:id/schedules | ADMIN / owning DOCTOR | day, startTime, endTime, maximumPatients |
| POST /appointments | PATIENT / RECEPTIONIST / ADMIN | doctorId, date, reason; staff also supplies patientId |
| GET /appointments | Signed in | Own/assigned appointments; staff operation list; capped at 200 |
| PATCH /appointments/:id/cancel | Owner PATIENT / RECEPTIONIST / ADMIN | Cancel WAITING appointment |
| GET /queue/:doctorId?date=YYYY-MM-DD | Signed in | Serial-only queue summary and own position |
| POST /queue/:doctorId/next | Owning DOCTOR / RECEPTIONIST / ADMIN | date; calls next for today |
| PATCH /appointments/:id/complete | Owning DOCTOR / RECEPTIONIST / ADMIN | Completes CALLED appointment |
| GET /patients/me | PATIENT | Patient profile |
| PUT /patients/me | PATIENT | Update profile |
| GET /patients | RECEPTIONIST / ADMIN | Patient lookup; optional search; capped at 50 |
| PUT /appointments/:id/record | Treating DOCTOR | notes, diagnosis, advice, followUp?, medicines[] |
| GET /patients/:id/history | Owner PATIENT / treating DOCTOR | Medical history |
| GET /admin/users | ADMIN | Optional search; most recent 50 users |
| GET /admin/analytics | ADMIN | Counts and today’s appointment status totals |

Passwords must be 12–128 characters. Email is trimmed and lowercased. Phone uses E.164-style international format. Unknown DTO fields are rejected. Appointment dates must be within 90 days and before the end of a same-day session.

Medicine objects have `medicine`, `dose`, `frequency`, `duration`; all four are required. Prescription decisions are authored by doctors, not generated by this application.
